Where each number comes from
  • From the cable (packets read before the driver touches them): motor speed measured from the lidar's own packet timestamps; lost packets from the lidar's sequence counters; input voltage, 12 V rail, current from the lidar's status packet (power = input voltage × current); board temperatures from the point-packet header.
  • From ROS (what a robot program receives): point cloud rate (5 s average), longest gap between clouds in each second, points with a return, scans narrower than 900 columns, delay from scan start to arrival, IMU rate.
  • From the PC: CPU use, UDP packets dropped because the receiving socket was full, packets dropped by the network card, driver CPU.
  • How to read it: motor speed stays at 600 rpm while ROS rate drops → the problem is after the lidar (network, PC or driver). Motor speed drops or voltage sags at the same time → power or the lidar itself. Lost packets on the cable → cable or switch. UDP drops → PC too slow or socket buffer too small.
  • Voltage and current scale (0.01 V / 0.01 A) is read from the driver's field names; confirm it once with a multimeter.
